# 链路物流助手：客户使用指南

启用后，你可以直接向 AI 提出链路物流业务需求，例如“比较发美国的渠道”“按刚才的报价下单”“查这几票的轨迹”。AI 会补齐必要信息，再使用你的链路账号查询或办理业务。

## 1. 下载技能包

- [客户 Skill ZIP](../downloads/link-logistics-assistant-v0.2.0.zip)
- [查看 Skill 内容](../skills/link-logistics-assistant/SKILL.md)
- [下载文件的 SHA-256 校验清单](../downloads/checksums.json)

ZIP 中只有 `link-logistics-assistant/SKILL.md`。在支持自定义 Skill 的客户端导入；也可解压后按该客户端的说明放入技能目录。文件导入成功后，还需要连接下述业务工具，才能真实查询或下单。

客户端没有 Skill 或外部工具入口时，上传文件作为普通聊天附件不会赋予它查询和下单能力。

## 2. 连接你自己的链路账号

请向你的链路服务提供方获取对应环境的 API 网关、客户权限范围内的 `linkToken` 和 `customerKey`。将它们填到客户端的连接器安全配置中，不要发送到聊天窗口，也不要编辑 Skill 文件写入凭证。

支持 `mcpServers` 配置和本地 stdio 的客户端，可以使用 [客户连接配置](../mcp-config.customer.example.json)：

```json
{
  "mcpServers": {
    "link-mcp": {
      "type": "stdio",
      "command": "uvx",
      "args": ["--from", "git+https://github.com/xiaolushanling/link-mcp.git", "link-mcp"],
      "env": {
        "LINK_PROFILE": "customer",
        "LINK_API_BASE_URL": "https://demo.linkl.com.cn/api",
        "LINK_TOKEN": "YOUR_CUSTOMER_SCOPED_LINK_TOKEN",
        "LINK_CUSTOMER_KEY": "YOUR_CUSTOMER_KEY"
      }
    }
  }
}
```

把示例网关改成你实际使用的环境，保留 `/api`，不包含 `/lmsservice` 等服务路径；不要原样使用凭证占位值。已有客户连接由管理员提供时，按管理员给出的地址和认证设置连接即可。

本地 Git 方式需要 Git、Python 3.11+ 和 [uv](https://docs.astral.sh/uv/getting-started/installation/)，并确保客户端能找到 `uvx`。如果需要指定其绝对路径，请由管理员在 `command` 中填写。

验证尚未同步到 Git 的本地 MCP 版本时，使用 [客户本地连接配置](../mcp-config.customer.local.example.json)，将其中的 Python 和项目路径改成 MCP 的实际安装位置。先按 [link-mcp 项目说明](https://github.com/xiaolushanling/link-mcp) 准备连接器环境；该配置直接启动本地 MCP，不从 Git 下载旧版本。Git 配置用于已经发布了客户模式和分段文档查询能力的 MCP 版本。

`customer` 模式只开放 22 个客户业务工具和 3 个本地文档工具，固定使用配置中的客户身份，不接收会话参数指定客户密钥。可以叠加 `LINK_READ_ONLY=true` 只开放 11 个查询业务工具和 3 个文档工具，或通过 `LINK_SERVICES` 限定业务。

此配置是一位客户的一组凭证。业务服务仍必须校验客户权限与运单归属；不要给不同客户分发同一组管理员凭证。当前服务不提供多客户账号绑定中心，不能将一个固定凭证的公共 HTTP 地址当成多客户授权入口。

## 3. 验证连接

重启或重新连接客户端，启用「链路物流助手」，对 AI 说：

> 检查链路物流助手的客户连接是否配置完整，不要显示凭证，也不要下单。

AI 应通过 `link_list_services` 确认客户模式、凭证配置状态和可用服务。即使没有填写凭证，文档工具仍能工作，但不能办理业务。`oauthLogin` 不是获取这些 API 凭证的入口。

## 4. 试着办理业务

| 你可以这样说 | 你会得到什么 |
| --- | --- |
| 两箱普通货发美国，帮我比较渠道和运费 | AI 补问邮编、件重尺寸等必要条件，展示真实报价和时效 |
| 就选刚才的第二个渠道，继续下单 | 沿用对应报价，核对必要订单资料，按授权提交 |
| 查询客户单号 TEST000000001 的国际物流轨迹 | 最新状态、节点和需要关注的异常 |
| 把这票尾派单的面单给我 | 对应业务实际返回的标签文件或链接 |
| 查一下我的余额和未付款金额 | 按币种展示工具实际返回的金额 |
| 取消客户单号 TEST000000001 的尾派运单 | 定位运单，核对取消对象和授权，报告实际结果 |

表中的 TEST 单号仅展示说法，请替换成自己的真实单号。报价是接口给出的预估，实际费用以业务结算为准。获取面单文件不等于打印机已经完成打印。

AI 不应为了补齐面单、重新显示结果或连接超时而重复创建订单；遇到“结果待核实”，先核实原客户单号。

## 5. 豆包与其他平台

豆包工作模式的自定义 Skill、连接器入口和支持的传输方式，需要以你实际使用的客户端版本和账号能力为准。标准 ZIP 提供完整的单文件工作流；导入后仍需在该入口配置可用连接器。不要把本地 stdio 的 JSON 直接填进只接收远程 MCP 地址的表单。

如果希望通过豆包官方应用插件渠道提供服务，交付与审核要求不同，见 [豆包适配说明](../platforms/doubao/README.md)。这里的客户 ZIP 不是该渠道的完整提审包。

其他平台同样要分别验证“能加载 Skill”“能连接工具”“能以客户身份执行任务”。客户端名字出现在说明里，不代表它的所有版本都通过了真机验证。

## 6. 更新与常见问题

- **更新 Skill**：下载新版本 ZIP，按客户端说明替换；版本号和 SHA-256 可在校验清单中核对。
- **更新 Git 工具**：在管理员终端执行 `uvx --refresh --from git+https://github.com/xiaolushanling/link-mcp.git link-mcp --help` 后重新连接客户端。生产使用也可将 Git 来源固定到已发布的完整提交或 tag。
- **显示未配置或权限不足**：在客户端安全设置中检查环境与凭证，联系服务提供方处理，不要将密钥粘贴给 AI。
- **找不到订单**：核对业务、单号和单号类型；不要改用其他客户身份试查。
- **没有报价**：补齐影响报价的资料，或根据返回说明调整条件；AI 不应估造价格。
- **只会解释、不会真实操作**：先检查连接器是否启用，单独导入 Skill 文件不会建立业务连接。

## 交付验证情况

项目提供工具范围、身份注入、参数校验、模拟业务调用和 MCP 协议检查，以及 [客户场景验收表](customer-acceptance.md)。这些检查不等于你所在客户端的真机测试，也不证明真实承运商、计费或打印行为。上线前应由服务提供方使用授权测试账号完成目标客户端联调。
